# AGENTS.md

Rules for agents working in this repository.

## What this is

Echelon Analytics (`ea.js`): privacy-first, self-hosted, cookieless web
analytics. One SQLite database, one script tag. Deno with Fresh 2 and Preact
islands, Vite and Tailwind v4. AGPL-3.0.

- `echelon-analytics/`: the application. All commands run from here.
  `routes/` (tracking endpoints, admin UI, REST API), `lib/` (all backend
  logic, `lib/db/` for SQLite), `hotpath/` (Rust crate built to WASM),
  `islands/`, `components/`, `tests/` (`tests/e2e/` needs Chromium).
- `docs/`: the public site. `scripts/`: deploy, rollback, smoke test, release
  tagging. `confs/`: deployment configuration.

## Rules

- `CLAUDE.md` holds the architecture and the detailed rules. Read it and follow
  it; it applies to every agent, not only Claude. The ones agents most often
  get wrong:
- Change a tracking endpoint's behaviour in its `serve*` function, not in the
  route file, and keep `tests/fast-path_test.ts` holding the fast path and the
  route to the same answer.
- Bot score thresholds come from `lib/bot-threshold.ts` (`CLEAN_SQL`,
  `BOT_SQL`). Never hand-type a range such as `BETWEEN 0 AND 49`.
- Everything that counts or limits addresses keys on `networkKey(ip)`.
- All state is in memory: one Deno worker only, never `--parallel`.
- `lib/hotpath-wasm.ts` is generated by `deno task build:hotpath`. Do not edit
  it by hand.
- Keep `CLAUDE.md` current when you change architecture it describes.
- No secrets in the repository. `.env` stays untracked; `.env.example` holds
  names only.
- Do not run `scripts/deploy.sh`, `scripts/rollback.sh` or
  `scripts/tag-release.sh`. Releases and deploys are the owner's.
- Open a pull request and stop. Never push to the default branch.

## Verify

`.pi/verify-cmd` is the fast gate. Run it before you say a change is done. It is
`cd echelon-analytics && deno task check`: format, lint, type-check and the
server-side tests. The E2E tests (`deno task test:e2e`) are not in it.

## Commits

Releases are one line, `Release vX.Y.Z` then a dash and what changed, made by
the owner.
For a pull request write a plain one-line subject that says what changed.
